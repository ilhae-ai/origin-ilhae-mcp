# origin-ilhae-mcp 설계서

> 대상 독자: 이 MCP를 유지보수하거나 확장할 개발자
> 근거: 내부 조사 문서, 공개 구현 6종 비교(2026-11-01)

## 1. 목표와 차별점

- Windows와 Origin 2021 이상에서 Claude Code·Claude Desktop이 Origin을 제어한다.
- 한국 연구실·기업에 배포할 수 있는 품질을 목표로 한다.
- 공개된 Origin MCP 6종 중에 한국어 환경을 다루는 곳은 없다. 그래서 다음 세 가지를 차별점으로 삼는다.
  1. 한국 환경 최적화
  2. 물리·전자공학 특화
  3. 결과 검증과 배포 편의성

## 2. 아키텍처

```
Claude Code/Desktop ─stdio─▶ MCP 서버 (Python 3.10+, mcp 2.x MCPServer)
                               │  tools/core.py · korea.py · physics.py
                               │  app.py: 직렬화 잠금 · 경로 검사 · 백업 · verify · 한국어 ToolError
                               ▼
                        transport/router.py (AutoBackend)
                     ┌─────────┴──────────┐
        (우선) bridge_client.py      (대체) com_client.py
           TCP 127.0.0.1:47021          외부 originpro + 전용 COM 스레드
           토큰 인증                      │
              ▼                          ▼
   Origin 내장 Python                 실행 중인 Origin
   ilhae_bridge.py (timer→pump)
              └──────── 공통: bridge/ilhae_ops.py (Python 3.8 호환) ────────┘
   watchdog.py: 시간 초과 시 Origin 대화상자(#32770) 탐지·보고·(선택) 자동 닫기
```

핵심 결정은 다음과 같다.

| 결정 | 이유 |
|---|---|
| 브리지와 COM이 같은 `ilhae_ops.py`를 공유 | 조작 코드를 한 벌만 유지하면 된다. 경로에 따라 동작이 달라지지 않는다 |
| `ilhae_ops`는 Python 3.8 문법 | Origin 2021~2023의 내장 Python이 3.8이다. 2023b부터는 3.11 |
| 브리지는 스레드 없이 LabTalk `timer`에서 `pump()` 호출 | originpro 호출이 항상 UI 스레드에서 일어나고, 내장 Python의 스레드 제약을 피한다 |
| 측정 파일은 서버(Python)가 읽어 데이터만 Origin에 전달 | 한글 경로와 CP949 인코딩 문제가 Origin까지 가지 않는다 |
| 물리 계산은 서버의 numpy/scipy, Origin은 그림만 | macOS에서도 수치를 단위 테스트로 검증할 수 있다 |
| 상태를 바꾸는 op는 실행 후 값을 다시 읽어 `applied`로 반환 | Origin은 잘못된 명령을 조용히 무시하는 경우가 많다. `verify.py`가 요청값과 비교해 판정한다 |
| AutoBackend는 요청을 보내기 전에 실패한 경우만 재시도 | 보낸 뒤 끊긴 경우까지 재시도하면 같은 작업이 두 번 실행될 수 있다 |
| 툴 실행 전체를 `app.lock`으로 직렬화 | 여러 단계로 된 툴이 Origin 안에서 서로 섞이지 않게 한다 |

## 3. 멈춤 대응 (3단계)

1. **예방**
   - `messagebox`, `file_dialog`, `asksave=True`는 쓰지 않는다.
   - 내보낼 폴더를 미리 만든다.
   - 같은 이름의 파일은 미리 지우거나 `FILE_EXISTS` 오류를 낸다. 덮어쓰기 확인 대화상자가 뜨지 않게 하기 위해서다.
2. **탐지**: 툴별 시간 초과(기본 60초, 피팅 120초)가 지나면 `watchdog`이 Origin 프로세스의 대화상자 제목과 본문을 한국어 오류에 넣는다.
3. **복구**
   - `ILHAE_AUTO_DISMISS=1`이면 대화상자에 WM_CLOSE를 보내 닫는다.
   - COM 경로는 이전 작업이 끝날 때까지 새 요청을 `COM_BUSY`로 막는다.

## 4. 보안

- **허용 폴더**: `ILHAE_ALLOWED_ROOTS` 안의 절대 경로만 허용한다.
  - `..`이 든 경로와 이름 앞부분만 같은 다른 폴더(예: `data` 허용인데 `data_evil`)는 거부한다.
  - 용도별로 확장자를 제한한다(읽기, 프로젝트, 내보내기).
- **토큰**: `%LOCALAPPDATA%\origin-ilhae\token`에 저장한다. 이 폴더는 기본적으로 본인 계정만 접근할 수 있다. 비교는 `hmac.compare_digest`로 한다.
- **바인딩**: 127.0.0.1에만 연결을 받는다. Windows에서는 `SO_EXCLUSIVEADDRUSE`로 다른 프로세스가 같은 포트를 가로채지 못하게 한다.
- **LabTalk**: 기본으로 툴 자체를 등록하지 않는다. 켜도 `confirm=true`, 차단 목록 검사, 사전 백업을 거친다.
  - 차단 대상: Python 실행, 외부 프로그램, 파일 삭제, `system.*` 설정 변경, DLL, `exit` 등
  - 차단 목록은 사고 방지용이며 완전한 샌드박스는 아니다.
- **자동 백업**: `project_new`, `project_open`, `labtalk_run` 전에 현재 프로젝트를 타임스탬프가 붙은 사본으로 백업한다(덮어쓰지 않음).

## 5. 한국 환경 처리

| 문제 | 처리 |
|---|---|
| CP949 CSV | `korea/encoding.py`: BOM → UTF-8 엄격 디코딩 → CP949 → charset-normalizer 순서로 판별. UTF-8을 먼저 시도해야 글자가 깨진 채로 "성공"하지 않는다 |
| 한글 헤더와 단위 | "전압(V)", "Current [mA]", "I / A"를 이름과 단위로 분리한다. 단위 행은 괄호로 감싼 값이나 실제 단위 이름일 때만 인정한다 |
| 단위 환산 | mA, nF, kHz 등을 SI 단위로 바꿔 계산한다(`si_factor`) |
| 한글 경로 | `korea/paths.py`: `auto`이면 doctor의 한글 경로 시험을 통과하기 전까지 영문 임시 폴더를 거친다 |
| 사용자 이름이 한글인 PC | `%TEMP%`에도 한글이 들어간다. 그러면 임시 폴더로 `C:\Users\Public\origin-ilhae\stage`를 쓴다 |
| 한글 문자열을 LabTalk에 전달 | 소스 코드 리터럴 대신 `set_lt_str`로 변수에 넣은 뒤 대입한다. 코드 페이지 영향을 피하기 위해서다 |
| 한글 글꼴 | 맑은 고딕을 기본으로 하고 한국어 별칭을 인식한다(맑은 고딕, 함초롬바탕 등). 적용 후 글꼴 번호를 다시 읽어 확인한다 |
| 그림 규격 | `presets/*.json` 5종. 모두 `verified:false` 초깃값이며, 투고 규정을 확인한 뒤 수정한다 |
| HWP | `그림{번호}_{제목}.emf`로 저장하고, 넣을 폭(mm)과 캡션 제안을 함께 반환한다 |
| 장비 CSV | `instruments/*.json` 프로필 사용. 형식이 뚜렷한(행 표지가 있는) 프로필을 먼저 검사한다 |

## 6. Phase 0 검증 항목 (Windows 실기 필수)

macOS에서는 Origin을 실행할 수 없다. 그래서 아래 항목은 Windows PC에서 `ilhae_poc.py`(Origin 스크립트 창에서 실행)와 `origin-ilhae-mcp doctor`로 확인해야 한다.
- 대상: Origin **2021**, **2023b 이상**(내장 Python 3.11), 그리고 **2026**(originpro 관련 변경 가능성)
- 방법: PoC 결과 JSON을 `docs/poc-results/`에 모아 버전별로 비교한다.

| # | 항목 (코드 위치) | 실패 시 대응 |
|---|---|---|
| 1 | 한글 왕복: LabTalk 변수, 리터럴, 열 긴 이름·단위·주석, 축 제목 (`kr_roundtrip`) | 리터럴만 실패하면 `set_lt_str` 경로만 사용(현재 설계). 열 이름까지 실패하면 버전별 우회 로직 추가 |
| 2 | 한글 경로 내보내기 (`kr_roundtrip` 6번) | `ILHAE_KR_PATH_MODE=stage`를 기본값으로 |
| 3 | `font(Malgun Gothic)`이 정상 번호를 돌려주는지, 미설치 글꼴이면 무엇을 돌려주는지 (`graph_set_font`) | 미설치 판별 로직을 보강 |
| 4 | `add_plot(colyerr=)` 인자 이름 (`graph_create`) | 오차 열을 E로 지정한 뒤 플롯하는 방식으로 교체 |
| 5 | `set_cmd("-w N")` 선 굵기 단위 (`graph_set_options`) | 배율 상수 수정 |
| 6 | `page.width/height`와 `page.resx`로 계산한 mm 크기 (`page_set_size`) | 단위 확인 후 환산식 수정, 또는 `expGraph` 크기 옵션으로 교체 |
| 7 | `save_fig(width=)` 지원 여부 | 미지원이면 `expGraph`로 교체 |
| 8 | `NLFit.set_param` 메서드 이름 | 버전별로 분기 |
| 9 | 브리지 `timer` 방식: UI가 느려지지 않는지, 사용자 timer와 충돌하지 않는지 | 0.2초로 늦추거나 Origin Apps 방식(.opx) 브리지로 전환 |
| 10 | COM 경로에서 `op.attach()`가 이미 실행 중인 Origin에 붙는지 | `win32com.client.GetActiveObject("Origin.ApplicationSI")`로 대체 |
| 11 | Origin 2026의 `_PyOrigin`에서 내장 Python 브리지가 동작하는지 | 2026 전용 import 분기 |

## 7. 테스트 전략

- `tests/test_physics.py`: 정답을 아는 합성 데이터로 수치를 검증한다(다이오드 n·Rs, Vth, SS, Mott-Schottky N·Vfb, FFT, 피크, Bode, Ea).
- `tests/test_korea.py`: CP949·UTF-8 판별, 메타데이터·단위 행·B1500 형식 해석, 한글 임시 폴더 우회, 프리셋.
- `tests/test_security.py`: 허용 폴더, 이름 앞부분만 같은 폴더 공격, LabTalk 차단·허용, verify 판정.
- `tests/test_bridge.py`: 실제 TCP 소켓으로 브리지 규약 확인(한글 왕복, 토큰 거부, 시간 초과). 브리지 파일의 **Python 3.8 문법 호환**도 검사한다.
- `tests/test_server.py`: 가짜 Origin(`FakeBackend`)으로 MCP 툴을 통합 테스트한다. `ignore` 옵션으로 Origin이 명령을 조용히 무시하는 상황을 재현해 `mismatch` 판정을 확인한다.

## 8. 남은 작업 (로드맵)

1. **Phase 0 실기 검증**과 그 결과 반영(최우선)
2. Origin Apps(.opx) 패키징: 버튼 하나로 브리지 시작·중지(Origin의 `mkOPX` 필요)
3. 장비 프로필 확충: 실제 Keithley·B1500·국내 장비 샘플 파일 확보
4. 국내 학회지·학위논문 규격 수치 확인 후 프리셋을 `verified: true`로
5. 그래프 템플릿 저장과 재적용, 배치 처리(폴더 안 파일 일괄 분석)
6. PyPI 배포와 설치 마법사(사내 배포용 오프라인 wheel 묶음)
